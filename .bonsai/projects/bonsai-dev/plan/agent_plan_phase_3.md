**Objective:** Make code mapping operate through repository-local map workspaces with resumable roadmap/state, optional flat scoped plans, source/map identity checks, separate generated output, and map-specific completion, while retiring the legacy `map_state.md` model.

**Inputs:** Approved `.bonsai/specification.md`, `requirements.md`, and `architecture.md`; the active Phase 3 roadmap; the completed Phase 1 workspace-routing seam and Phase 2 shared lifecycle; current `.bonsai/skills/code_maps.md`, `.bonsai/prompts/implementation.md`, `.bonsai/skills/handoff.md`, mapping templates and guides, focused workspace tests, and representative embedded output at `.bonsai/maps/niagara4/code_map.md`.

**Out of Scope / Do Not Do Yet:** Renaming or reworking the Web UI project/map creation prompts; project-to-map associations; broad README or stale-reference cleanup; migration or expansion of the existing Niagara generated map; generic workspace types, registries, nested map-plan trees, automatic source resolvers, dependency-to-map registries, or changes to human-owned final truth or map calibration.
