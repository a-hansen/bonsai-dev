## Objective & Scope

**Objective:** Establish and prove the smallest shared workspace-entry and routing seam for projects and maps while preserving ordinary project startup behavior and keeping active workspace identity session-local.  
**Inputs:** Approved `.bonsai/specification.md`, `requirements.md`, and `architecture.md`; the active Phase 1 roadmap; the current `.bonsai/start.md` and `.bonsai/prompts/implementation.md`; the live `bonsai-dev` project; existing repository testing conventions.  
**In Scope:** Define the small declarative `workspace.md` contract for the two approved workspace types; add the live `bonsai-dev` project entry; make repository-local startup resolve default/named projects and explicit maps, load the selected entry, and hand workspace identity to the implementation kernel; make the kernel reconstruct and route by workspace type without eager knowledge loading; add focused dependency-free fixture validation for the Phase 1 startup/routing seam; reconcile execution memory.  
**Out of Scope / Do Not Do Yet:** Shared handoff/lifecycle generalization; map `agent_plan.md`/`agent_state.md` lifecycle and scoped map plans; migration or retirement of `map_state.md`; project-to-map associations; project/map creation prompt renames or rework; migration of unrelated existing projects or generated-map directories; generated-map changes; README or broad category-guide cleanup; compatibility aliases; a generic `workspaces/` directory, registry, or third workspace type.  
**Expected Deliverables:** `../../task-tracker/workspace.md`; bounded workspace-aware updates to `.bonsai/start.md` and `.bonsai/prompts/implementation.md`; `tests/bonsai_workspace_foundation.py` with isolated project/map fixtures and negative cases; reconciled `.bonsai/projects/bonsai-dev/agent_plan.md`, `.bonsai/projects/bonsai-dev/agent_state.md`, and this phase plan.

## Execution Constraints

- **Implementation Scope:** The active Bonsai standard's workspace-entry/startup/routing artifacts, the live `bonsai-dev` workspace entry, focused isolated validation, and this project's agent-owned execution memory.
- **Approved Boundaries:** Projects and maps remain concrete directories under `.bonsai/projects/` and `.bonsai/maps/`; unqualified startup remains project-oriented and prefers `projects/main`; map startup is explicit; `workspace.md` is small, declarative, and free of volatile execution state; active identity is session-local; bootstrap resolves identity and loads only the workspace entry before handoff; the implementation kernel performs lazy workspace reconstruction and branches into project- or map-specific behavior; missing or invalid entries are surfaced rather than guessed around.
- **Durable Contracts:** Phase 1 establishes the concrete `workspace.md` entry format and the `start.md` -> selected `workspace.md` -> implementation-kernel routing handoff. The contract must represent exactly `project` and `map`, supply only stable routing information, and must not become a generic workspace registry or execution-state format.
- **Human Review Focus:** Review the proposed `workspace.md` fields and examples, default/named project and explicit-map resolution rules, missing/invalid-entry failures, bootstrap/kernel ownership boundary, lazy-loading guarantees, and the fixture expectations before authorizing implementation beneath the contract.
